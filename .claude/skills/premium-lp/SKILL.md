# ハイクオリティLP（アニメーション＋60秒PV）

山西水産LP（完成形: https://ystudio.yamanisi.co.jp/yamanishi-suisan/ ）を、お客さんと何往復もして作った型。
勝ち筋は **派手さではなく「事実の強さ」と「その会社にしかない素材」**。AIが量産する“高級っぽいテンプレ”は、
見る人にすぐ見抜かれて価値が下がる。だから事実を掘り、本物の写真とロゴを主役にし、動きはその事実を印象づけるためだけに使う。

進め方は **FACT → WHY → SHAPE → MAKE → DO → LEARN**。

---

## クイックスタート

```bash
# 静的サイトのリポジトリ（GitHub Pages など）で
bash <このスキル>/scripts/init-project.sh <プロジェクトのルート> <ページのフォルダ名>
#   → <ページ>/index.html（完成形の見本）、tools/lp（動き・ビルド・動作チェック）、tools/pv（60秒PV）
cd tools/lp && npm install && npm run build && OUT_DIR=<スクショ置き場> npm run check
```

- スターターの `index.html` は山西水産の**完成品そのもの**。構成・CSS・動きの付け方の見本として使い、
  文言・写真・色・リンクはすべてその会社の事実に入れ替える（山西水産の文言が1つでも残ったら事故）。
- 動作チェックは Chromium を使う（`CHROMIUM_PATH`、既定 `/opt/pw-browsers/chromium`）。
- 既にスターターが入っているリポジトリ（例: ystudio-plus は `tools/motion-lab/` と `tools/yamanishi-pv/`）ではそれを使う。

## 1. FACT — 素材と事実を掘る（ここが品質の8割）

1. **既存の公式サイト・LPのソースを探す**。ネットに出られない環境でも GitHub にあることが多い
   （`list_repos` → `add_repo` → 読み取り clone）。文章・数字・年号・商品名・リンク・電話・SNSを抜き出し、
   `references/fact-sheet.md` の表に入れる。埋め込み画像（base64）も取り出せる。商品カードの画像は
   CSSクラスと突き合わせて**どの商品の写真か確定**させる（違う商品の写真を付けると信用を失う）。
2. **自社写真を探す**（SNS投稿用の画像リポジトリなど）。現場・人・手元・仕入れの写真は、どんなストック写真より効く。
   縮小一覧（コンタクトシート）を作って目で選ぶ。
3. **食い違いは本人に確認してから全ページ一括で直す**（例: 明治12年は1879年。1878年と書いたページがあった）。
4. **足りない素材は作らない**。「要素材」として本人に頼む（チャットに画像を送ってもらえば使える）。
   ネットの写真はライセンスが確認できる物だけ。この環境から素材サイトに出られないことも多い。

> 盛らずに、掘る。肩書き・数字・日時・固有名詞・受賞・メディア掲載は出典のあるものだけ。
> 推測で埋めたコピーは、本人が一読で気づき、全体の信用を落とす。

## 2. SHAPE — 見た目の方針（AIっぽさを消す）

**避ける量産型**: 濃紺/黒＋金、細い明朝、ガラス風カード、金のカスタムカーソル、`—— HISTORY` 風の細線ラベル、
光のグラデーション、全部が下からふわっと出るだけの動き。（元LPがまさにこれで「AIサイトっぽい」と言われた）

**代わりにやること**
- **主役は本物**: ロゴ（手描きなら最高）、商品写真、現場写真、代表の顔。
- **色は3色**: 例 生成り `#f4efe4`・墨 `#1b1a18`・朱 `#e0442a`。色数が少ないほど高く見える。
- **書体は業種の声**: 老舗・和食・水産は**筆文字**。無料で安全なのは Google Fonts の `Yuji Syuku`。
  同色のふちで太らせると極太毛筆に寄る（`-webkit-text-stroke:.035em currentColor; paint-order:stroke fill;`）。
  市販の毛筆（黒龍など）はWeb用ライセンスが要るので、本人が持っていればファイルをもらって差し替える。
  極太ゴシックは「かっこ悪い」と言われた。本文は `Zen Kaku Gothic New`、手書きの添え字に `Yusei Magic`。
- **大きな文字は墨一色＋朱の落款**。文字の中にイメージ写真を入れる（background-clip:text）のは「変」と言われた。
- **太い線・ずらした影**（`border:2-3px` ＋ `box-shadow:6px 6px 0`）。ステッカーのような手触りが人の気配を出す。
- **スマホのスクロールはブラウザ本来のまま**。なめらかスクロール（Lenis）はPCだけ、画面が止まる区間はスマホで短く。
  指で重いと感じた時点で、どんな演出も逆効果になる。

## 3. MAKE — 構成と演出

| 順 | セクション | 中身 | 演出（`references/animation-recipes.md`） |
|---|---|---|---|
| 0 | オープニング | ロゴが業種らしく動く一発芸（ふぐ屋＝ぷくっと膨らむ） | ロゴのばね＋円で抜ける |
| 1 | ヒーロー | 1〜2文字の墨の筆文字＋朱の落款 → 線の中へ飛び込み料理写真へ | 墨の文字に吸い込まれる |
| 2 | PV | 60秒PV（音ありはボタンで） | 額縁が傾きから正面へ |
| 3 | 歴史 | 代ごとに色を変えた5枚 | 縦スクロールで横に流れる |
| 4 | 土地の物語 | その土地だけの事実を「数字」で（例 1592→1888 ふぐ解禁） | 年号カウンター、×が○に |
| 5 | 産地 | 大きな文字の帯 | 速度で傾くマーキー |
| 6 | 約束 | 3つ。写真は現場の本物 | 重なるカード |
| 7 | 商品 | 元サイトと同じ並び・同じリンク | 写真がカーソルに付いてくる |
| 8 | 代表 | 顔写真＋出典つきの本人の言葉 | 傾いて入る写真・ステッカー |
| 9 | 購入 | モール・自社EC・電話・SNS | 行が朱で塗りつぶされる |
| 10 | フッター | 社名を巨大な筆文字で | 1文字ずつぷくっ |

- 大技は3つまで（例: 文字に吸い込まれる・年号カウンター・横年表）。大技は必ず**その会社の事実**と組にする
  （年号カウンターは「禁止令と解禁の年」という事実があるから効く。無い会社に付けても空振り）。
- 構成は会社に合わせて足し引きする。土地の物語や歴史が薄い会社は、職人の工程・数字の実績などに置き換える。
- 動きの基本（Motion の書き方、Framer Motion からの読み替え）は `motion-site` スキル、または `references/animation-recipes.md`。

## 4. PV（60秒・曲と連動）

`references/pv-pipeline.md`。要点だけ:
- 実写真＋筆文字アニメを1コマずつ描いて MP4/WebM にする（外部の動画生成AIは使えない前提）。
- 会社のテーマソングがあれば譜面から音源化し、**場面の切り替えを小節の頭に**合わせる（96BPMなら1小節2.5秒、60秒＝24小節）。
  曲が無ければ `music.js` に24小節のコード進行を書けば同じ仕組みで鳴る。削るのは前半、サビと締めの一言は残す。
- 写真と言葉の意味を合わせる（「一匹一匹」に刺身はNG → 魚を手に取る写真）。

## 5. 確認（公開前に必ず）

1. `npm run build` → `OUT_DIR=… npm run check`（PC・スマホ＝タッチ端末・動き控えめの3通り。エラー0・隠れたまま0・横はみ出し0・PV再生）
2. スクショをコンタクトシートにして**全部目で見る**（折り返し、重なり、写真の中の文字と字幕の矛盾）。
3. `references/review-checklist.md` を上から潰す（★はお客さんに実際に指摘されたもの）。
4. 動画をユーザーに送るときは**毎回ファイル名を変える**（同名だと古い版が開いて「直ってない」と言われる）。
5. 耳で聴けない・実機で触れないなど、確認できなかったことは正直に伝える。

## 6. DO — 公開

- GitHub Pages は既定ブランチ（master/main）の中身だけが出る。ブランチのままではリンクは404。
- 公開（PR→マージ）は本人が「公開して」「リンクちょうだい」と言ってから。それまではスクショと動画で見てもらう。
- 新しいページは `noindex`・トップからリンクなしで出し、本人がOKしたら外す。
- マージ済みのPRには積まない。次の修正は最新の既定ブランチから作り直したブランチ＋新しいPR。

## 7. LEARN — 学びを残す

お客さんの「好き/嫌い」は次の案件でも必ず効く。会社ごとに `references/<会社>-case.md` を作り、
確定した事実・好み・NG・宿題を書き足す（見本: `references/yamanishi-case.md`）。
