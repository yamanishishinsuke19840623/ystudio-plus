# ハイクオリティLP（アニメーション＋PV）を作る

山西水産LP（`yamanishi-suisan/index.html`、公開 https://ystudio.yamanisi.co.jp/yamanishi-suisan/ ）で
お客さん（やまちゃん）と何度もやり取りして固まった型。**見た目の豪華さより「事実の強さ」と「その会社にしかない素材」で勝つ。**

基本の循環: **FACT → WHY → SHAPE → MAKE → DO → LEARN**（やまちゃんのプロデュース手順そのまま）。

---

## 0. 最初に必ずやる（素材と事実を掘る）

1. **既存の公式サイト・LPのソースを探す**。ネットに出られなくても GitHub にあることが多い。
   `list_repos` で本人のリポジトリを見て、`add_repo` → 読み取り clone（例: `yamanishi-suisan` = lp.yamanisi.co.jp）。
   - 文章・数字・年号・商品名・リンク・電話・SNS を抜き出す（`references/fact-sheet.md` の表に入れる）
   - 埋め込み画像（base64）も取り出せる。商品カードの画像は CSS クラスと突き合わせて**どの商品の写真か**を確定させる
2. **自社写真のリポジトリを探す**（例: `yamanishisuisan-ig-images` = Instagram 投稿用）。
   現場・人・手元・仕入れの**本物の写真**が一番効く。コンタクトシート（縮小一覧画像）を作って目で選ぶ。
3. **食い違いを洗い出して本人に確認**（例: 「明治12年（1878年）」→ 明治12年は1879年。元LPが1879）。
   直すときは**全ページを grep して一括で揃える**。
4. 足りない素材は**作らない**。「要素材」としてリストにし、本人に頼む（チャットに画像を直接送ってもらえば使える）。

> 盛らずに、掘る。FACT 以外を事実として書かない。肩書き・数字・日時・固有名詞・受賞・メディア掲載は出典のあるものだけ。

## 1. 見た目の方針（AIっぽさを消す）

**やってはいけない量産型**: 濃紺/黒＋金、細い明朝、ガラス風カード、金のカスタムカーソル、細い線の見出し飾り、
グラデの光、`—— HISTORY` 風の英字ラベル、全部ふわっと下から出るだけの動き。
（元LPがまさにこれだった → 「AIサイトっぽい、もともとあるからはずして」と言われた）

**やること**:
- **主役は本物**: 会社のロゴ（手描きなら最高）、商品写真、現場写真、代表の顔。イラストや抽象図形で埋めない。
- **色は3色に絞る**: 例 生成り `#f4efe4`・墨 `#1b1a18`・朱 `#e0442a`（＋差し色に空色/生成りの濃淡）。
- **書体は「その業種の声」**: 老舗・和食・水産なら**筆文字**。
  - 無料で安全: Google Fonts の `Yuji Syuku`（筆）。同色のふちで太らせて極太毛筆に寄せる:
    `-webkit-text-stroke:.035em currentColor; paint-order:stroke fill;`
  - 「黒龍」など市販の毛筆はWeb用ライセンスが要る。持っていればフォントファイルをもらって差し替える。
  - 本文は `Zen Kaku Gothic New`、手書きの小さな添え字に `Yusei Magic`。
  - ゴシックの極太（Dela Gothic One 等）は「かっこ悪い」と言われた。和の老舗には使わない。
- **線は太く、影はずらす**: `border:2-3px solid 墨` と `box-shadow:6px 6px 0 墨`（ステッカー風）。角丸カード＋ぼかし影はAIっぽい。
- **スマホのスクロールはブラウザ本来のまま**。なめらかスクロール（Lenis）はPCだけ、固定区間はスマホで短く。
- **手書きのひとこと**（`Yusei Magic`、少し傾ける）を見出しの上に置くと人の気配が出る。

## 2. ページ構成の型（物語の順番）

| 順 | セクション | 中身 | 主な演出（`references/animation-recipes.md`） |
|---|---|---|---|
| 0 | オープニング | ロゴが「ぷくっ」と膨らむ（業種に合う一発芸） | ロゴのスケール＋円で抜ける |
| 1 | ヒーロー | 1〜2文字の大きな**墨一色**の筆文字＋朱の落款 → スクロールで文字の線の中へ飛び込み、料理写真へ（文字の中に写真は入れない） | 墨の文字に吸い込まれる |
| 2 | PV | 60秒PV（音ありはボタンで） | 額縁が傾きから正面へ |
| 3 | 歴史 | 初・二・三・四・次（代ごとに色を変える） | 縦スクロールで横に流れる |
| 4 | 土地の物語 | その土地ならではの事実を「数字」で見せる（例 1592→1888 ふぐ解禁） | 年号カウンター＋×が○に |
| 5 | 産地/市場 | 帯で流す大きな文字 | 速度で傾くマーキー |
| 6 | 約束 | 3つ。写真は**現場の本物** | 重なるカード |
| 7 | 商品 | 元LPの商品と同じ並び・同じリンク | 行に乗ると写真がカーソルに付いてくる |
| 8 | 代表 | 顔写真＋本人の言葉（出典つきの引用だけ） | 写真が傾いて入る・ステッカー |
| 9 | 購入 | モール・自社EC・電話・SNS | 行が朱で塗りつぶされる |
| 10 | フッター | 社名を巨大な筆文字で | 1文字ずつぷくっ |

コードの見本: `yamanishi-suisan/index.html`（HTML/CSS）＋ `tools/motion-lab/src/yamanishi.js`（動き。関数ごとに1演出）。
新しい会社のページは**このフォルダを丸ごと複製して中身を入れ替える**のが最速。

## 3. PV（60秒）

`references/pv-pipeline.md` に手順。要点:
- 外部の動画生成AIは使えない前提。**実写真＋文字アニメを1コマずつ描画**（`tools/yamanishi-pv/`）して MP4/WebM にする。
- BGMは会社のテーマソングがあれば**譜面から音源化**し、**小節に映像の切り替えを合わせる**（96BPMなら1小節2.5秒）。
- 長さは**60秒**（24小節）。サビの歌詞と「〇〇と生きる　社名」の締めは削らない。削るのは前半。
- 写真と言葉の意味を合わせる（「一匹一匹」に刺身はNG → 魚を手に取る写真）。

## 4. 確認（公開前に必ず）

1. `cd tools/motion-lab && npm run build && OUT_DIR=<scratchpad> npm run check`
   （PC・スマホ・動き控えめの3通り、エラー0・隠れたまま0・横はみ出し0・PV再生）
2. スクショを**コンタクトシートにして全部目で見る**（文字の折り返し、重なり、写真の中の文字と字幕の矛盾）。
3. `references/review-checklist.md` を上から潰す。
4. 動画をユーザーに送るときは**毎回ファイル名を変える**（`pv-v3.mp4` 等）。同名だと古い版が開いて混乱する。

## 5. 公開

- GitHub Pages は **master の中身だけ**が出る。ブランチのままではリンクは404。
- **公開（PR→マージ）はユーザーが「公開して」「リンクちょうだい」と言ってから**。それまではPR止め・スクショと動画で確認してもらう。
- 新しいページは `noindex`・トップからリンクなしで出し、本人がOKしたら外す。
- マージ済みPRには積まない。次の修正は master から作り直したブランチ＋新しいPR。

## 6. 学び（LEARN）を残す

お客さんの「好き/嫌い」は次も必ず効く。`references/yamanishi-case.md` のように**会社ごとの好み・NG・確定した事実**を書き足す。
